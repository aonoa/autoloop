# 安全模型

本文说明 Agent Autoloop 的信任边界、密钥、事件资料隔离、权限限制和已知风险。操作建议见 [SECURITY.md](../SECURITY.md)，协议细节见 [protocol.md](protocol.md)。

## 信任边界

系统假设：

- 安装者信任本机操作系统账号；
- 安装者信任自己安装的插件；
- 来源密钥只交给可信来源；
- worker 密钥只交给可信工作机；
- 通道密钥只交给可信通道进程；
- 本人密钥只由本人持有；
- 规则文件由本人维护，是可信配置。

系统不假设：

- 外部事件文字可信；
- Webhook 发送者身份一定可信；
- 卡片链接不会被转发；
- Agent 不会犯错；
- 插件不会执行恶意代码；
- 单机部署能抵御本机管理员。

## 密钥

| 密钥 | 能力 | 泄露影响 |
| --- | --- | --- |
| source | 发事件、查自己的事件结果、发 tell | 可伪造事件，消耗 Agent 时间 |
| worker | 领活、心跳、为分配给它的 `elsewhere` 任务发 `tell` 或提问 | 可领取并执行任务，消耗额度 |
| channel | 领卡片、报告投递、以平台身份回答 | 可查看和回答卡片 |
| owner | 看全局、回答、结案、停止、暂停、恢复、补跑、手动运行、删除密钥 | 能控制运行和看全局，但不能发事件、领活，也不能直接改 `rules.json` |
| 轮次 token | 提交特定轮次结果 | 只能影响该轮 |
| 卡片链接 | 回答特定卡片 | 持有即授权，7 天有效 |

密钥只保存哈希；轮次 token 和卡片链接由 `master.key` 派生。提交某轮的 `started/result` 要用该轮 token，不是 worker 密钥。`master.key` 泄露等同于能伪造这些 token。

删除密钥立即失效，长轮询和日志流也会关闭；已经领取的轮次仍可用该轮 token 提交结果。

## 规则才是指令

事件字段进入提示词的只有：

- 来源显示名；
- 事件类型；
- `subject`；
- `link`。

这些字段在入口经过字符集和长度校验。`summary`、`detail` 等自由文字只写入资料文件，并明确标注为资料，不作为指令。

Agent、目录、权限、通道、收件人和交付仓库只由可信规则决定。事件里带 `cwd`、`agent`、`access` 等字段会被拒绝。

这降低但不消除提示注入风险。Agent 仍可能误读资料；最坏影响应限制在规则给定的目录和权限内。

## 只读轮次的真实边界

研判和预演轮次：

- 内核强制下发 `access: "read"`；
- 提示词要求只判断、不做事、不改文件、不对外发消息；
- 不授予正式轮的执行权限；
- 研判只写决定，预演只写报告。

但 `access` 由 Agent 插件翻译，不是内核沙箱：

- Codex 的 `read-only` 有实际沙箱；
- Claude Code 的 `plan` 仍取决于本机审批规则；
- `command` 类 Agent 完全由命令自己决定；
- 插件配置和本机 CLI 配置可能放宽限制。

需要强隔离时，使用系统账号、容器或独立机器。

## 卡片与链接

- 卡片回答只认第一次；
- 通道回答必须核验平台身份和消息引用；
- 配了 `answerers` 时只允许名单内身份；
- 本人可以直接回答和结案；
- 卡片链接是持有即授权，7 天有效；
- 链接只应发给本人，不应发到公开群或公开仓库；
- 飞书按钮由平台核验身份，比链接更安全。

## 事件与跳数

- 事件按来源 + id 去重；
- 回执事件继承本轮最大 `hops + 1`；
- 超过 8 层只记录、不派发，并通知本人；
- 回答和复查延续原深度；
- 外部来源的新事件可以从 0 开始；
- 这防止处理链无限循环，不防止恶意来源持续发新事件。

## Policy 与身份

- `allowlist` 和 `bots` 只在同一来源内比较；
- 不同来源的账号不做映射；
- 空 `actor` 在开启 Policy 后被拒绝；
- `admission: "named"` 要求事件点名 Agent；
- 身份由来源插件从平台字段提取，插件必须正确实现；
- 规则自发事件由 `emits` 授权，不再走来源 Policy。

Policy 是准入控制，不是身份认证系统。它依赖来源插件和平台本身的可信度。

## 插件

插件是本地代码，加载即执行：

- 可以读本机文件；
- 可以访问网络；
- 可以使用环境变量中的密钥；
- 可以启动子进程。

因此：

- 只安装可信插件；
- 安装前阅读代码；
- 不要把不可信仓库直接 `add` 到生产环境；
- 插件崩溃不会让中台退出，但可能影响通道或 worker；
- 插件应只使用 `node:` 模块，减少供应链风险。

## Agent 权限

`access` 是建议性权限，由插件翻译：

- `read`：只读；
- `edit`：可改工作目录；
- `full`：完整权限，不审批。

只读不等于读不到密钥。Agent 以本机账号运行，能读该账号可读的文件。需要隔离时使用系统账号或容器。

`command` 类 Agent 不消费 `access`，权限完全由命令本身决定。

## 交付与代码执行

交付插件：

- 不检出或运行 PR 的代码、测试、配置、hooks；
- 只把裸 Git 对象变成文字快照；
- 默认 Codex 审查忽略用户配置和记忆；
- 审查使用只读快照；
- 合并和发布以 GitHub 状态为准；
- 健康 URL 默认只允许 HTTPS；
- 本机测试才允许 HTTP 127.0.0.1。

自定义审查命令由项目管理者负责提供同等约束。

## 数据与备份

备份包含：

- 事实日志；
- 主密钥；
- 配置中的密钥；
- 规则；
- Webhook 秘密。

备份等同于密钥，必须：

- 存放在私有目录；
- 限制访问；
- 加密传输；
- 不提交到 Git；
- 不粘贴到公开讨论。

日志和 Agent 输出可能包含业务数据，也应按敏感数据管理。

## 多机与网络

- 工作机不需要开放入站端口；
- 中台公网部署必须使用 HTTPS；
- 反向代理不得缓存 `/v1/*`；
- 不要直接暴露 SQLite 文件；
- 不要在多台机器间共享同一个 `hub.db`；
- 多项目共享中台时，所有项目共享密钥和事实库，不是硬隔离。

## 已知限制

- 没有操作系统级沙箱；
- 没有多租户硬隔离；
- 没有集中身份和细粒度 RBAC；
- 没有防重放的外部 Webhook 时间窗（依赖来源 id 去重）；
- 卡片链接持有即授权；
- `command` 类 Agent 的权限不受内核控制；
- 提示注入只能降低，不能根除；
- 单机 SQLite 没有高可用；
- 强杀恢复不等于断电恢复证明；
- 未做完整安全审计。

按 [SECURITY.md](../SECURITY.md) 私下联系维护者，不在公开 Issue 中披露利用细节。

报告时提供：

- 受影响版本；
- 复现步骤；
- 影响范围；
- 是否需要特定配置；
- 建议修复方向。
